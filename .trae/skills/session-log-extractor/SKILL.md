# 带过转写提取器

把历次带过的会议转写（含大量OOC场外内容）翻译成存档状态更新。产出必须交给用户审查。

## 职责边界

- 本技能产出：存档回填建议（GM 视角，供审查）+ 直接更新冒险地点存档正文（房间描述/GM备注/宝藏与机制）+ 提取摘要
- 玩家视角的战报由 game-report-generator 技能产出
- 衔接方式：本技能提取的局内操作事实可作为 game-report-generator 生成战报的依据
- 本技能不生成战报文档；需要战报时衔接 game-report-generator

## 何时调用

- 用户提供了带过转写记录，要求"更新状态"、"回填状态"、"根据转写修改存档"
- 存档正文里还有"待转写确认"或"存疑"标注的项，且用户给出了对应转写

## 输入

- 转写文件（语音转写，如 `战役/记录/<地点>.txt`）
- 对应存档（如 `战役/存档/<地点>/<地点>.md`），整份文档是更新对象——房间正文、GM备注、宝藏表与机制段落都按带过结果改写

## 核心流程

1. **通读转写与存档**：先完整读转写，再通读存档的房间正文、GM备注、宝藏表与机制段落。
2. **分辨OOC，只留局内操作**：
   - 排除：建卡过程（属性/装备/星象/毛色）、玩家间互怼、现实话题（风扇、天气、飞书、QQ、网速）、规则结算讨论（伤害/豁免怎么算）、分赃讨价还价、升级计算。
   - 保留：玩家在游戏内实际做的动作、事件结果、NPC状态变化、物品得失、战斗胜负、机关触发、交易达成。
3. **以剧情事实为准，不信说话人标签**：
   - 语音转写的"说话人01/02…"不可靠，同一角色可能被识别成多个编号；玩家角色名/昵称混杂（例：小玉/鱼友玉、天猫/睫毛/风月牙）。按"谁做了什么"判断，不按名字对号入座。
4. **逐房间回填，直接改写正文**：不新建状态章节或状态表，把带过结果写进原文对应段落，保持文档原有结构：
   - 朗读文本：已被取走/清除/破坏的内容直接写进描述（如"角落原本堆着的一捆卷轴已被取走，只留几根解开的细绳"）。
   - GM备注（引用块）：补充事件结果与当前现状（如"旧头目已被击杀，新头目接替"）。
   - 机制/谜题/宝藏段落：联动改写（如"陷阱已被触发""封印的水晶被整块取走，谜题只剩一圈划痕""电缆已被射爆，不再通电"）。
5. **修正与转写冲突的既有状态**：旧状态若与转写矛盾（如虚构的"王冠归位、鬼魂安息"），以转写为准重写，并在摘要中说明改动。
6. **不确定就标注**：转写里没有依据的项保留"待转写确认"或标"存疑"，不要脑补。
7. **输出回填建议与提取摘要供用户审查**：按存档列出回填建议（房间状态/宝藏/派系变更）、关键局内操作、排除的OOC类型、与旧状态冲突的修正点。用户确认后再收尾。

## 项目特定规则（Mausritter 西征）

- **预兆规则已移除**：转写里的"预兆"字样是历史记录，不要写进存档/生成器。
- **层级隔离**：状态只写进冒险地点存档正文，不提升到战役层。
- **世界演化**：存档里的演化推演（如"新头目接替""鼠群愈发绝望"）是GM层推进，可保留，但与转写冲突的部分以转写为准。
- 存档不新建"状态"章节或"| 房间 | 现状 |"表，直接改写原文段落；更新范例参考 `战役/存档/` 下已按此方式更新的地点文件。
