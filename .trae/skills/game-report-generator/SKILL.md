# 游戏报告生成器

根据带过会议/语音转写与冒险地点文件，生成游戏报告（战报）。可与 session-log-extractor 流程衔接使用。

## 职责边界

- 本技能产出：玩家视角的战报
- session-log-extractor 产出：存档回填建议（GM 视角，供审查）+ 直接更新冒险地点存档正文（房间描述/GM备注/宝藏与机制）
- 衔接方式：session-log-extractor 提取的局内操作事实可作为本技能生成战报的依据
- 本技能不产出回填建议、不改写存档文件；回填相关事项衔接 session-log-extractor

## 输入

- 会议转写：本场带过的对话/语音转写文本（OOC 与局内对话混合）
- 冒险地点文件：本场前往的冒险地点模组（`[地点名].md`，含导入/房间/遭遇/宝藏/当前状态）
- 战役文档（可选）：用于核对势力动向、世界演化

## 处理流程

1. 分辨 OOC 与局内操作：剔除 GM 规则解释、桌面讨论、玩笑等非局内内容；保留玩家的行动、决定、对话与结果
2. 提取关键事件：去了哪些房间/地点、遭遇了什么、战斗结果、拿了什么、触发什么机制、与哪些 NPC 互动
3. 对照冒险地点文件：用转写结果核对文件中的当前状态（哪些房间已探索、哪些宝藏被取走、哪些生物被清除、派系有何变化），作为战报中"未完成事项""前方已知危险"的依据
4. 产出前自检：每条事实用一句"玩家怎么知道的？"过一遍——只保留当场可观察的，删掉任何依赖档案标签、GM 备注、战役后总结、推断性结论的条目
5. 产出游戏报告

## 输出格式

报告应尽量简短，作为共享地图上的一条记录颗粒度，不展开叙事段落。

### 游戏报告（玩家视角，极简条目模板）

```markdown
日期：[场次时间或序号]
队伍：[PC]
目标：[本场任务/委托]
发现：[地点、NPC、宝藏、机关、传闻；只列观察所得]
怪物：[遭遇的生物]
战利品：[带回/交付的物品]
未完成事项：[没做完的事、未解的谜]
传闻：[本场带出的新传闻线索]
```

每条压缩到一行（≤80 字），禁止长段落，禁止复述冒险地点档案里已写明的内容。

- 字段满则写、未触则省；不要为了凑齐把所有字段都写出来
- 单条超长就再砍：合并同主语、删修饰词、把人名/物名换成速记、用顿号并排
- 例外：`发现`/`战利品`/`未完成事项` 因条目多，可用 2–4 个短分行的子项，每子项仍 ≤80 字
- 输出先列满足字段的，未触发的字段整条删除，不要留空行

## 规则

- 报告用客观、自然的叙述，禁止 AI 腔（宣传性语言、三段式、枚举罗列、meta 语言）
- 报告只写玩家当场能观察到的内容：只采用桌面公开掷骰、当场听见/读到/看到、玩家自身行动的结果，不引入冒险地点档案里的设定层信息
- 报告不泄露 GM 秘密：玩家未发现的真相、未公开的机制、未读到的具体文字一律不写入玩家可见的报告
- 房间与地点的称呼以 GM 现场口头描述为准（如"废弃大厅""偏斜走廊""陵墓密室"），写玩家亲耳听过的环境称谓；不要直接复制档案里的"房间+序号"标题（如"房间 2""房间 6"），也不要用未在桌面说出口的档案正式名
- 判定口径：以下内容不进报告——
  - 冒险地点档案中写在 GM 备注、遭遇表、宝藏表里的怪物属性、欲望、机制数值
  - 玩家未亲眼看到标签文字的"具体写了什么"
  - 未在桌面公开掷骰的豁免规则、伤害公式、状态效果
  - 设定层（如派系动向、幕后动机、上一场或下一场的演化）
  - 可疑但玩家未做出明确判断的猜测
  - 档案里"房间+序号"式的标题编号（如"房间 2""房间 6"）：玩家只见过 GM 描述的环境，未见过档案里的房间名标题/编号，不得直接复制——应改写为 GM 现场口头用过的环境称谓
  - 带过结束后 GM 才补的世界观元信息（聚落类型、势力归属、市场体系等），即便 GM 当众说出口，仍属于战役后总结而非局内观察
- 泛化原则：规则与示例适用于所有战役，不引用特定战役的专有设定作为约束
