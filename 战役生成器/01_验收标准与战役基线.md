# 模组验收标准与战役生成基线

## 一、文档用途

本文件是战役生成器优化项目的**验收尺子**与**方向基线**，供所有后续修改对照打分，避免优化失焦。提示词优化任务同时遵守工作区规则《提示词工程守则》（`.trae/rules/prompt-engineering-rules.md`）。

项目界定与架构现状（2026-08-12）：

- 生成器已重构为两个物理隔离的层级（子目录隔离，互不渗透）：
  - `战役层/00-04`：战役生成器（六角格地图/定居点/派系/季节/流言/冒险地点分配）
  - `冒险地点层/00-05`：冒险地点生成器（独立自包含，可单独生成或被战役层调用）
- 根目录 `00_主提示词.md` 为总入口：用户声明用途后路由到对应层级
- 现有 5 个冒险模组是试验产物，效果已达标，作为升级基础保留

本文件包含三部分：

1. 冒险模组验收标准（100 分制，可复用打分）
2. 战役模组结构定义（基于世界构建.md 原版规则）
3. 生成器已知缺陷清单（修复状态 + 验证项）

## 二、冒险模组验收标准（100 分制）

### 评分总表

| 维度 | 权重 | 核心理念 |
| --- | --- | --- |
| 即插即用与机制完整 | 25 | 拿到就能开跑，机制无残缺 |
| 结构与布局 | 15 | 布局与房间描述自洽 |
| 叙事一致与钩子落地 | 20 | 导入承诺全部落点 |
| 主题氛围与感官 | 15 | 微观视角、感官细节、记忆点 |
| 遭遇与宝藏 | 15 | 多样性、价值匹配、表不绑房 |
| 版式与AI感 | 10 | 规范遵守、无AI腔 |

### 各维度检查点

#### 1. 即插即用与机制完整（25）

| 分值 | 检查点 |
| --- | --- |
| 5 | 每个陷阱/谜题/障碍含三要素：触发条件 / 解法 / 后果 |
| 3 | 陷阱明显且致命，有明确危险与多种解法 |
| 5 | 数据块完整：HP / STR / DEX / WIL / 护甲 / 攻击 / 重击 / 欲望 |
| 3 | 数据量级符合生物列表参考表，无离谱数值 |
| 4 | 规则符合：豁免写属性名不写 DC、每回合豁免≤1 次、光源按需 |
| 3 | 无悬空机制（写了但玩家用不上 / 没接上下文） |
| 2 | GM 无需二次加工即可开跑 |

#### 2. 结构与布局（15）

| 分值 | 检查点 |
| --- | --- |
| 5 | 布局图存在，且与每个房间的"前进"一一对应（无图中连接但无描述、无描述但图无连接） |
| 3 | ≥2 条进入深层的路径，≥1 个环路 |
| 2 | 核心秘密/主要宝藏在最深处 |
| 2 | 入口房间提供方向选择 |
| 3 | 房间连接物理自洽；跨房间关联（尸体来源、生物流动）已交叉标注 |

#### 3. 叙事一致与钩子落地（20）

| 分值 | 检查点 |
| --- | --- |
| 6 | 导入/背景承诺的事件与人物全部落到具体房间或遭遇条目，无悬空承诺 |
| 5 | 待寻对象可识别：朗读文本或可见场景有外观/行为特征，玩家凭文本即可认出，不靠 GM 引用块点破 |
| 3 | 背景（可揭露）与 GM备注（绝密）分层正确，无越界 |
| 3 | 秘密、居民、目标、物品在全文描述一致 |
| 3 | 导入无规则性内容，酬金只出现一次 |

#### 4. 主题氛围与感官（15）

| 分值 | 检查点 |
| --- | --- |
| 4 | 朗读文本 ≥2 种感官细节（无标签） |
| 3 | 微观视角：日常物放大为景观/威胁/宝藏 |
| 3 | 一句话主题与全文贯彻（核心秘密贯穿） |
| 3 | 氛围基调与各房间描写一致 |
| 2 | 每个房间有独特记忆点，不雷同 |

#### 5. 遭遇与宝藏（15）

| 分值 | 检查点 |
| --- | --- |
| 3 | 遭遇表 6 条各有"正在做的事"，不限定具体房间 |
| 3 | ≥2 条存在非战斗解决路径 |
| 3 | 遭遇与居民/第二派系/核心秘密相关，非单一类型 |
| 3 | 宝藏价值与风险匹配，无离谱价格 |
| 3 | 唯一宝藏与随机表隔离；随机表通用、不绑定具体房间 |

#### 6. 版式与AI感（10）

| 分值 | 检查点 |
| --- | --- |
| 2 | 无扩折号（——）、双引号（""）、分页符（---）、表情符号 |
| 2 | 数字与英文和中文之间无空格 |
| 2 | 无 AI 腔：宣传性语言、三段式、枚举罗列、meta 语言 |
| 2 | 章节结构符合生成器规范（标题层级、引用块、表格格式） |
| 2 | 无半角标点错乱、空行过度等格式问题 |

### 评分方法

- 逐项按检查点给分（每项 0 到满分，可给半分）
- 总分 = 六维之和；>85 优秀 / 70-85 合格可发行 / 50-70 需修订 / <50 重做
- 评分必须引用模组中的具体行号作为证据，禁止凭印象打分

## 三、战役模组结构定义（新基线）

### 层级隔离原则

战役模组由两个互相隔离的层级构成，层级之间不互相渗透。**已通过子目录结构物理隔离落地**（`战役层/` 与 `冒险地点层/`），并在两个层级主控中各内置层级边界声明：

| 层级 | 持有信息 | 不得持有 |
| --- | --- | --- |
| 战役层 | 六角格地图、定居点、派系、季节、流言；每个冒险地点只持有名称/主题/位置/关联派系/起始钩子/概要 | 冒险地点内部细节（房间、机制、唯一宝藏、NPC数据） |
| 冒险地点层 | 单个冒险地点的完整模组（`冒险地点层/00-05` 全流程输出） | 战役层参数（派系进度、季节天气、地图位置），除非冒险地点明确引用 |

- 战役层调用冒险地点生成器时，只传"地点主题关键词"，不传派系/季节等信息
- 冒险地点生成器是独立子流程：可单独生成一个冒险地点，也可被战役层调用，两种模式下输出相同
- 流言与遭遇表可概略引用冒险地点，但不引用其房间内部细节

### 世界构建.md 内容使用盘点

世界构建.md 的内容现已全部落地到生成器（战役层模块已实现，冒险地点层已修复缺口）：

| 世界构建.md 章节 | 现状 |
| --- | --- |
| 六角格工具箱（类型/地标/细节表） | 已内嵌至 `战役层/01` |
| 老鼠定居点（规模/治理/习俗/特征/产业/事件/命名/酒馆） | 已内嵌至 `战役层/01` |
| 派系（目标/资源/进度标记/战团） | 已内嵌至 `战役层/02` |
| 季节（天气/季节事件/恶劣天气惩罚） | 已内嵌至 `战役层/03` |
| 流言（d6 真实/部分真实/虚假） | 已内嵌至 `战役层/03` |
| 冒险地点-主题/居民/秘密 | 已使用（`冒险地点层/01`） |

待办：无（多入口原则与原版宝藏表体系已内嵌）。

### 派系来源

方向（2026-08-12）：派系构建优先从已有冒险模组的居民/势力提取素材。素材不静态存放于生成器内部，**战役生成任务进行时按需从用户提供的冒险模组中提取**，提炼为跨地点的战役级派系（同一派系可横跨多个冒险地点，不是每个独立地点算一个派系），再补缺。

### 1. 六角格地图层

- 5×5 六角格，中心放置友好定居点
- 每格：类型（乡村/森林/河流/人类城镇）+ 地标 + 地标细节，一行描述
- 标出待细化的地标作为冒险地点，分散布置，数量不限，可随战役推进持续新增

### 2. 定居点层

- 规模（2d6 取低值，农庄→城市）
- 治理方式（掷骰+规模修正）
- 居民习俗（d20）+ 显著特征（d20）+ 产业（d20，城镇/城市两个）
- 当前正在发生的事件（d20）
- 命名（前缀+后缀）+ 酒馆/客栈

### 3. 派系层

- 3-4 个派系，每个包含：
  - 名称与一句话身份
  - 目标（需要 2-5 个进度标记完成，取决于复杂程度）
  - 资源
  - 与其他派系的关系（目标应互相竞争或冲突）
- 派系活动应能被流言与遭遇表引用

### 4. 季节层

- 选定起始季节（春/夏/秋/冬）
- 天气表（2d6）+ 季节事件表（d6）
- 恶劣天气旅行需 STR 豁免否则获得疲惫状态

### 5. 流言层

- d6 流言表：1-3 真实 / 4-5 部分真实 / 6 虚假
- 每条流言必须指向具体地点或派系活动（禁止空泛表述）

### 6. 冒险地点层

- 选择地标细化，数量不限；已确定开跑的地点复用现有冒险地点生成器全流程产出独立文件，其余给出主题 + 起始钩子 + 概要（可延迟细化）
- 有关联派系的注明关联（谁在此、为何在此、竞争什么），无则写明当地势力

### 战役运行期约定（2026-08-13 战役检查沉淀）

战役文档是活文档，随派系推进与带过状态持续改写。长期战役（西征团）下追加以下基线：

- 活文档：战役文档默认按可扩展、可覆写设计；非标准记号必须当场注明含义（如 ●● 表示目标已达成，转为长期守望）；带过地点存入 `存档/[地点名]/[地点名].md`，战役文档引用其路径
- 回填核对：冒险地点层产出独立文件后，回查战役概览表钩子、流言中的术语与模组导入是否一致；GM 内部信息（派系名、NPC名、钩子、存档）固定用名，流言允许模糊
- 全量引用：战役文档的完全细化引用必须覆盖所有已存在的地点文件（含存档），否则 GM 无法二次探查
- 克制原则：新增规则前先对照原版规则与实际玩法，两者皆无依据则不添加（资源数量门槛、地点数量上限、首次会话等均属此列移除项）

### 战役层验收要点（在冒险模组验收标准之外追加）

| 检查点 |
| --- |
| 地图格子填充完整，每格有可读的一行描述 |
| 派系目标与资源完整，派系间存在冲突或竞争 |
| 流言逐条指向具体地点或派系 |
| 有关联派系的冒险地点注明关联 |
| 季节天气/事件落地为可执行的规则效果 |
| 完全细化的冒险地点通过冒险模组验收标准 |
| 非标准记号（如 ●●）已当场注明含义 |
| 文件引用覆盖全部已存在地点（含存档） |
| 钩子/流言中的名字与独立模组一致 |

## 四、生成器已知缺陷清单

### 状态判定方法

判定一个缺陷是"现行版本仍会犯"还是"已被修复的历史问题"，依据两条：

1. **规则是否已内嵌**：查 `冒险地点层/00-05` 提示词当前文本是否已包含对应规则/校验项
2. **最新模组是否仍犯**：以最新生成的模组（偏移学院、烛泉墓地）是否出现为准

模组代次判定：烛泉墓地、偏移学院为最新版本产物；病窟较新；风暴女王陵寝、蜂巢下的阴影为早期版本产物。因此风暴/蜂巢暴露的缺陷，若现行提示词已补规则，则降为"验证项"，不作为修复重点。
