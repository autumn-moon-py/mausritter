# 模组验收标准与战役生成基线

## 一、文档用途

本文件是战役生成器优化项目的**验收尺子**与**方向基线**，供所有后续修改对照打分，避免优化失焦。提示词优化任务同时遵守工作区根目录规则《提示词工程守则》（`../.trae/rules/prompt-engineering-rules.md`）。

项目界定与架构现状（2026-08-12）：

- 生成器已重构为两个物理隔离的层级（子目录隔离，互不渗透）：
  - `战役层/00-03`：战役生成器（六角格地图/定居点/世界演化/冒险地点分配与路途遭遇）
  - `冒险地点层/00-05`：冒险地点生成器（独立自包含，可单独生成或被战役层调用）
- 根目录 `00_主提示词.md` 为总入口：用户声明用途后路由到对应层级
- 现有 5 个冒险模组是试验产物，效果已达标，作为升级基础保留

本文件包含三部分：

1. 冒险模组验收标准（100 分制，可复用打分）
2. 战役模组结构定义（基于世界构建.md 原版规则）
3. 生成器已知缺陷清单（修复状态 + 验证项）

## 二、冒险模组验收标准（100 分制）

### 评分总表

| 维度 | 权重 | 核心理念 |
| --- | --- | --- |
| 即插即用与机制完整 | 25 | 拿到就能开跑，机制无残缺 |
| 结构与布局 | 15 | 布局与房间描述自洽 |
| 叙事一致与钩子落地 | 20 | 导入承诺全部落点 |
| 主题氛围与感官 | 15 | 微观视角、感官细节、记忆点 |
| 遭遇与宝藏 | 15 | 多样性、价值匹配、表不绑房 |
| 版式与AI感 | 10 | 规范遵守、无AI腔 |

### 各维度检查点

#### 1. 即插即用与机制完整（25）

| 分值 | 检查点 |
| --- | --- |
| 5 | 每个陷阱/谜题/障碍含三要素：触发条件 / 解法 / 后果 |
| 3 | 陷阱明显且致命，有明确危险与多种解法 |
| 5 | 数据块完整：HP / STR / DEX / WIL / 攻击 / 欲望；重击与护甲按生物特性填写（非所有生物都有） |
| 3 | 数据量级符合生物列表参考表，无离谱数值 |
| 4 | 规则符合：豁免写属性名不写 DC、每回合豁免≤1 次、光源按需 |
| 3 | 无悬空机制（写了但玩家用不上 / 没接上下文） |
| 2 | GM 无需二次加工即可开跑 |

#### 2. 结构与布局（15）

| 分值 | 检查点 |
| --- | --- |
| 5 | 布局图存在，且与每个房间的"前进"一一对应（无图中连接但无描述、无描述但图无连接） |
| 3 | ≥2 条进入深层的路径，≥1 个环路 |
| 2 | 核心秘密/主要宝藏在最深处 |
| 2 | 入口房间提供方向选择 |
| 3 | 房间连接物理自洽；跨房间关联（尸体来源、生物流动）已交叉标注 |

#### 3. 叙事一致与钩子落地（20）

| 分值 | 检查点 |
| --- | --- |
| 6 | 导入/背景承诺的事件与人物全部落到具体房间或遭遇条目，无悬空承诺 |
| 5 | 待寻对象可识别：朗读文本或可见场景有外观/行为特征，玩家凭文本即可认出，不靠 GM 引用块点破 |
| 3 | 背景（可揭露）与 GM备注（绝密）分层正确，无越界 |
| 3 | 秘密、居民、目标、物品在全文描述一致 |
| 3 | 导入为定居点所见所闻驱动，无委托人与酬金；无规则性内容 |

#### 4. 主题氛围与感官（15）

| 分值 | 检查点 |
| --- | --- |
| 4 | 朗读文本 ≥2 种感官细节（无标签） |
| 3 | 微观视角：日常物放大为景观/威胁/宝藏 |
| 3 | 一句话主题与全文贯彻（核心秘密贯穿） |
| 3 | 氛围基调与各房间描写一致 |
| 2 | 每个房间有独特记忆点，不雷同 |

#### 5. 遭遇与宝藏（15）

| 分值 | 检查点 |
| --- | --- |
| 3 | 遭遇表 6 条各有"正在做的事"，不限定具体房间 |
| 3 | ≥2 条存在非战斗解决路径 |
| 3 | 遭遇与居民/第二派系/核心秘密相关，非单一类型 |
| 3 | 宝藏价值与风险匹配，无离谱价格 |
| 3 | 唯一宝藏与随机表隔离；随机表通用、不绑定具体房间 |

#### 6. 版式与AI感（10）

| 分值 | 检查点 |
| --- | --- |
| 2 | 无扩折号（——）、双引号（""）、分页符（---）、表情符号 |
| 2 | 数字与英文和中文之间无空格 |
| 2 | 无 AI 腔：宣传性语言、三段式、枚举罗列、meta 语言 |
| 2 | 章节结构符合生成器规范（标题层级、引用块、表格格式） |
| 2 | 无半角标点错乱、空行过度等格式问题 |

### 评分方法

- 逐项按检查点给分（每项 0 到满分，可给半分）
- 总分 = 六维之和；>85 优秀 / 70-85 合格可发行 / 50-70 需修订 / <50 重做
- 评分必须引用模组中的具体行号作为证据，禁止凭印象打分

## 三、战役模组结构定义（新基线）

### 层级隔离原则

战役模组由两个互相隔离的层级构成，层级之间不互相渗透。**已通过子目录结构物理隔离落地**（`战役层/` 与 `冒险地点层/`），并在两个层级主控中各内置层级边界声明：

| 层级 | 持有信息 | 不得持有 |
| --- | --- | --- |
| 战役层 | 六角格地图、定居点、世界演化；每个冒险地点只持有名称/主题/位置/关联派系/状态（威胁等级写入格网元数据.json，起始钩子与情报在冒险地点文件内部）；世界任务详情可作为最小冒险级例外持有其自身所需的角色与场景数据 | 冒险地点内部细节（房间、机制、唯一宝藏、NPC数据），不得把冒险地点内部秘密搬入世界任务详情 |
| 冒险地点层 | 单个冒险地点的完整模组（`冒险地点层/00-05` 全流程输出） | 战役层参数（势力动向、地图位置），除非冒险地点明确引用 |

- 战役层调用冒险地点生成器时，只传"地点主题关键词"，不传势力动向等信息
- 冒险地点生成器是独立子流程：可单独生成一个冒险地点，也可被战役层调用，两种模式下输出相同
- 路途内容由战役层依据格网元数据.json的六向邻接列出定居点到地点的全部不重复最短路径；按每条路径经过的格子生成逐格独立内容，每格可用不同骰子、简短正文或无遭遇，共享格子共用内容；遭遇是否触发遵循旅行规则；固定遭遇不加前缀，遭遇的额外解释、GM信息、结果或反应统一放入备注列；不要求冒险地点层读取整张地图（D-13）
- 战役层输出拆为两个文件：战役主文件（标题/六角格地图含定居点/告示板/索引）与 `世界演化与冒险地点.md`（世界演化/冒险地点概览，与主文件同目录），主文件尾部索引指向独立文件；战役不设简介段落，定居点并入地图中心格描述、不单开章节

### 世界构建.md 内容使用盘点

### 势力来源

方向（2026-08-12，2026-08-18 更新）：势力构建优先从已有冒险模组的居民/势力提取素材。素材不静态存放于生成器内部，**战役生成任务进行时按需从用户提供的冒险模组中提取**，提炼为跨地点的战役级势力（同一势力可横跨多个冒险地点，不是每个独立地点算一个势力），再补缺。派系推进记账（资源/进度标记/每场d6推进）按实际玩法决定移除，改用时间流逝+剧情逻辑的演化规则。

### 1. 六角格地图层

- 5×5 六角格，中心放置友好定居点
- 每格：类型（乡村/森林/河流/人类城镇）+ 地标 + 地标细节，一行描述
- 标出待细化的地标作为冒险地点，分散布置，数量不限，可随战役推进持续新增

### 2. 定居点层

- 规模（2d6 取低值，农庄→城市）
- 治理方式（掷骰+规模修正）
- 居民习俗（d20）+ 显著特征（d20）+ 产业（d20，城镇/城市两个）
- 当前正在发生的事件（d20）
- 命名（前缀+后缀）+ 酒馆/客栈
- 以上全部并入地图中心格描述（2-4 句话），不单开章节

### 3. 势力与世界演化层

- 3 个势力（主从/附庸/代理合并计），每个包含：
  - 名称与一句话身份
  - 动向（具体可执行，不设进度标记、不记账）
  - 与其他势力的关系（动向应互相竞争或冲突）
- 输出演化规则：两次游戏之间时间流逝（默认约一周），世界按剧情逻辑演化，不掷骰
- 势力活动应能被路途遭遇引用

### 4. 冒险地点层

- 选择地标细化，数量不限；已确定开跑的地点复用现有冒险地点生成器全流程产出独立文件，其余给出主题+状态（可延迟细化）
- 有关联势力的注明关联（谁在此、为何在此、竞争什么），无则写明当地势力
- 威胁梯度按地点所在圈层分配（低/中/高），越远越危险；威胁等级写入格网元数据.json 的 tier 字段，不写入玩家文档
- 起始钩子与情报记录在冒险地点文件内部（导入/带过状态），概览表不持有
- 战役层根据格网元数据.json的六向邻接列出定居点到地点的全部不重复最短路径，并按途经格子生成逐格内容写入地点文件；共享格子共用内容，按旅行规则决定遭遇是否触发（D-13）

### 战役运行期约定（2026-08-13 战役检查沉淀）

战役文档是活文档，随世界演化与带过状态持续改写。长期战役（西征团）下追加以下基线：

- 活文档：地点文件只保留最新状态，按可扩展、可覆写设计；非标准记号必须当场注明含义；带过结果直接改写对应地点文件
- 回填核对：冒险地点层产出独立文件后，回查概览表与各地点文件中的名称术语是否与模组一致；GM 内部信息（势力名、NPC名、钩子、存档）固定用名，导入允许模糊
- 全量引用：战役文档的完全细化引用必须覆盖所有现存地点文件，否则 GM 无法二次探查
- 世界演化直接修改受影响地点、房间、内部遭遇及所有相关路径经过格子的内容；共享格子变化时同步所有相关路径；已不存在内容直接删除；不引入初始/当前双层、roomId、实体索引、版本或状态覆盖层（D-13）
- 克制原则：新增规则前先对照原版规则与实际玩法，两者皆无依据则不添加（资源数量门槛、地点数量上限、首次会话等均属此列移除项）

### 战役层验收要点（在冒险模组验收标准之外追加）

| 检查点 |
| --- |
| 战役主文件结构：标题/六角格地图（定居点并入中心格）/告示板/索引；世界演化与冒险地点写入独立文件 `世界演化与冒险地点.md`，索引已指向 |

| 势力动向与关系完整，势力间存在冲突或竞争；演化规则已输出 |
| 势力动向作用于荒野与冒险地点层面，不把定居点本身当目标 |
| 每个冒险地点文件内置情报、全部不重复最短路径及逐格路途内容；共享格子共用内容，遭遇触发遵循旅行规则；固定遭遇不加前缀，遭遇额外说明统一放入备注列 |

| 世界任务来源不只来自告示板；冒险地点NPC、路途NPC、势力行动或玩家已知事件引出的任务均有明确来源与触发入口，告示板只统计实际张贴的3-5条 |

## 四、生成器已知缺陷清单

### 状态判定方法

判定一个缺陷是"现行版本仍会犯"还是"已被修复的历史问题"，依据两条：

1. **规则是否已内嵌**：查 `冒险地点层/00-05` 提示词当前文本是否已包含对应规则/校验项
2. **最新模组是否仍犯**：以最新生成的模组（偏移学院、烛泉墓地）是否出现为准

模组代次判定：烛泉墓地、偏移学院为最新版本产物；病窟较新；风暴女王陵寝、蜂巢下的阴影为早期版本产物。因此风暴/蜂巢暴露的缺陷，若现行提示词已补规则，则降为"验证项"，不作为修复重点。

级别定义：P0 = 破坏一致性/可用性；P1 = 拉低品质；P2 = 规则已补、仅验证抽查。P0/P1 缺陷已于步骤2-5完成**规则层修复**，级别保留作为历史严重度参考。
