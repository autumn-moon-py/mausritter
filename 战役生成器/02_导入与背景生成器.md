# 子模块：导入与背景生成器

## 功能

为冒险地点生成玩家朗读文本和GM背景备注，让玩家获得冒险动机，GM掌握完整背景。

## 输入

- 冒险地点名称与主题
- 衰败原因
- 居民类型与目标
- 核心秘密

## 处理流程

| 6 | 贵族鼠 | d4×1000p |

### 2. 生成玩家朗读文本

玩家朗读文本是GM在会话开始时直接读给玩家的内容。先朗读，后展开冒险。

**格式要求**：
- 不使用引用块（>）
- 每句单独一段，简洁短句，便于GM朗读
- 第一句：点明委托人（身份 + 与玩家的关系）+ 一个直观外观印象
- 第二句：补充委托人的当前状态或性格细节
- 第三句：说明求助的具体原因或目标
- 第四句（可选）：以报酬和请求结尾
- 全部使用第二人称（"你们"）
- 不出现玩家朗读之外的任何背景细节——历史、衰败原因、秘密等全部放到GM备注中

**边界规则**：
- 玩家朗读只描述动机、外观、酬金，不写规则性内容
- 酬金只在玩家朗读文本中写一次，GM备注不重复酬金数字
- 玩家朗读不出现怪物弱点、伤害值、豁免类型等机制内容

**模板**：

[委托人身份+关系]曾[关系描述]，他/她[直观外观印象]

[这位委托人][状态/性格细节]

[求助原因：具体的、可感知的异常或目标]

[报酬金额]，求你们去看看

### 3. 生成GM背景备注

GM背景备注是供GM私下阅读的完整背景信息，包含冒险的所有关键信息。放在玩家朗读文本之后，使用 `## GM备注` 二级标题区分。

**必须包含**：
- 冒险地点的历史（建造、衰败、现状）
- 居民情况（类型、数量、目标、行为模式）
- 核心秘密的详细解释
- 委托人信息（姓名、身份、与玩家的过往、动机）
- 冒险原因（为什么现在需要冒险）
- 关键NPC的态度和可能的反应
- 与其他房间或地点的关联

**格式要求**：
- 不使用引用块
- 直接在 `## GM备注` 标题下用连贯段落叙述
- 信息完整，GM无需二次加工

**GM备注禁止项**（绝对不能写在GM备注里）：
- 怪物弱点描述（什么能伤害它）
- 具体伤害值和豁免类型
- 机制规则（陷阱如何触发、宝藏如何使用）
- 重复的酬金数字（已在玩家朗读出现）
- 房间内部的规则性描述（光源、检定频次等）

**正确做法**：机制性内容统一放在居民数据章节的引用块里、房间的###机制章节、宝藏表的GM备注列。GM备注只说"故事"，不说"规则"。

### 4. 简化钩子

钩子简化为"委托人发钱"，不需要复杂的钩子表。

**说明**：
- 委托人提供报酬
- 冒险原因在GM背景备注中交代
- 玩家朗读文本直接呈现冒险动机

## 输出格式

```markdown
# 导入

[玩家朗读文本第1句]

[玩家朗读文本第2句]

[玩家朗读文本第3句]

[玩家朗读文本第4句（如有）]

## GM备注

[GM背景备注：完整背景、委托人信息、冒险原因等]
```

**示例**：

```markdown
# 导入

灰烬谷的长老玛莎来找你们，她胡须发灰，说话时不停地搓爪子

三天前那场大风把村外的古墓掀了，现在有群生面孔在那儿翻东西，昨晚路过还听见金属碰撞的声音

那些强盗已经挖开了好几座贵族墓，听说风暴女王的陪葬品还没被找到，求你们去阻止他们

她愿意付50皮普

## GM备注

灰烬谷外的古墓是百年前为安葬风暴女王而建，守墓人一脉相传至今。玛莎的奶奶曾是最后一位守墓人，去世前将墓中秘密告诉了玛莎。三天前的风暴掀开了墓顶的石板，一群流浪鼠组成的强盗团伙趁机潜入，已经挖开了外围的几座贵族陪葬墓，正在寻找主墓室——里面据说埋着风暴女王的权杖和一柄能召唤雷云的银剑。强盗头目"独眼"格里克是个前雇佣兵，手下有5-6只老鼠，他们打算在下一场风暴来临时动手，因为那时守墓咒语最弱。玛莎找到你们是因为上个月你们帮她赶走过骚扰村庄的黄鼠狼，她愿意倾尽积蓄支付50皮普。
```
