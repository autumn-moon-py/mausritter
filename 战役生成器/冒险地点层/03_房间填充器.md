# 子模块：房间填充器

## 功能

根据主题与场景，生成冒险地点的所有房间，包含朗读文本、感官细节、机制、隐藏信息和连接关系。

## 输入

- 冒险地点名称与主题
- 衰败原因
- 居民类型与目标
- 核心秘密
- 氛围基调
- 房间数量

## 处理流程

### 1. 规划房间结构

在填充内容之前，先规划整体房间布局。

**原则**：
- 至少 2 条进入深层的路径
- 至少 1 个环路（A→B→C→A 或 A→B→D→C→A）
- 核心秘密/主要宝藏放在最深处
- 入口房间应提供方向选择
- 至少 1 个隐藏或备选入口（密道、破洞、侧门、地下通道），让玩家有绕过正面进入的选项；隐藏入口必须在具体房间的朗读文本或隐藏信息中找到落点，不能只存在于布局图上

**合理性要求**：
- 生物的出现必须符合逻辑，解释其存在的原因
- 不要为了增加趣味性而随意添加生物
- 如果生物出现在非巢穴房间，必须在隐藏信息中解释原因

**跨房间关联**：
- 若某个 NPC、物品或事件从其他房间进入本房间（掉落的尸体、逃来的伤者、流窜的生物等），必须在隐藏信息中明确标注其来源房间和抵达本房间的路径
- 若本房间的某物会出现在其他房间，同样需要在双方房间的隐藏信息里交叉标注
- 跨房间关联是 GM 维持全局一致性的关键，不能省略

**规模建议**：

| 房间数 | 结构建议 |
| --- | --- |
| 5-6 | 入口 + 2条分支（各1-2间）+ 深处1间，简单环路 |
| 7-9 | 入口 + 2条分支（各2-3间）+ 深处1-2间，一个环路 |
| 10-12 | 入口 + 3条分支 + 中层枢纽 + 深处2间，多个环路和秘密通道 |

**连接表（唯一事实来源）**：

规划完结构后，先输出一张连接表，作为之后所有"前进"和布局图的唯一依据：

| 房间 | 连接到的房间 |
| --- | --- |
| 1 入口 | 2 |
| 2 前厅 | 1、3、4 |
| ... | ... |

**核对规则**：

- 每个房间的`### 前进`必须与连接表逐条一致：连接表有的连接，"前进"必须写出；"前进"写的连接，连接表必须存在
- 连接必须双向：A→B 时，B 的"前进"必须能回到 A
- 布局图（组装阶段输出）必须与连接表一致，禁止出现连接表之外的路径
- 生成过程中若需增删连接，必须先改连接表，再同步改相关房间的"前进"与布局图

**复杂度预算**：

冒险地点的自定义复杂度必须有上限，防止多套特殊系统堆叠导致 GM 负担失控：

- 全局特殊系统（影响整个冒险的规则，如领域切换钟、暴露度计数）：最多 1 个
- 房间级自定义机制（标准表之外的原创机制）：全冒险最多 2 个
- 其余陷阱/谜题/障碍一律从标准表选择，或按标准表骨架改写，不得另创
- 判定标准：机制若需 GM 额外追踪状态（计数、计时、掷表），即计入预算；预算超限时，删除或简化次要机制

### 3. 编写房间内容

对每个房间，按以下模板编写：

**房间设计前置检查**：
- 陷阱/无光环境（按需）：默认玩家自带提灯等手提光源，不必每房点明场地光源。仅当房间明确禁止点火或关键氛围需借助固定光源时，在隐藏信息中标注安全光源的位置（如磷光苔藓、夜光蘑菇等）
- 房间之间的连接：必须符合物理逻辑。两个房间之间的连接必须是同一通道、同一楼梯、同一裂缝等，不能凭空出现
- 检定频次：每回合豁免不超过1次，陷阱/空房间的每回合豁免不超过1次

#### 3.1 朗读文本

**格式**：第二人称，2-4 句话，可直接读给玩家。

**必须包含**：
- 空间感：大小、形状、高低
- 至少 2 种感官细节（直接融入描写，不加任何标签或标注）

**可见场景实体**：
- 玩家进入房间能直接看见的生物、看守、明显物体（如蹲在洞口的哨兵、被拴住的苦力、插着钥匙的钉子），必须写入朗读文本，写直观外观或玩家能直接辨识的身份（如"一只皮毛泛光的瘦老鼠蹲在洞口边"、"一只守夜人哨兵蹲在洞口边"）
- 其隐藏动机、来源、战术意图等不可直接感知的信息（如"向每个进出者收一枚皮普"）放引用块
- 引用块不得承载可见场景描写，可见内容一律进朗读文本

**禁止项**：
- 不写具体豁免类型、伤害值、触发条件等规则性内容（如带豁免判定和伤害数值的机制描述）
- 朗读文本只描述感官现象（视觉、听觉、嗅觉、触觉等可观察的现象），具体豁免和后果放到 `###` 机制章节或 GM 须知

**感官词汇库**（仅供构思参考，写入时去掉标签直接描写）：

- 声：回声、滴水、嗡鸣、窸窣、尖叫风、死寂、研磨、碎裂、低吟
- 味：霉变、甜腻、酸腐、焦糊、金属、花蜜、腐肉、潮湿、尘土
- 光：昏暗、闪烁、银色微光、完全黑暗、彩色光斑、刺眼反光、磷光
- 温：冰冷、闷热、潮湿、干燥、温热、刺骨寒意
- 触：黏腻、粗糙、滑腻、刺痛、酥麻、柔软

**示例**：
你们挤过裂缝，进入一条倾斜向下的通道。墙壁上传来细微的嗡嗡声，像是有什么东西在蜂巢格子里面振动。甜腻的蜂蜜气味中混着一丝酸腐，越往深处越浓。左侧通道透出银色光芒，右侧向下延伸，越来越暗。

#### 3.2 隐藏信息

**格式**：使用 `>` 引用块。

**两类隐藏信息**：

1. **GM 须知**：玩家无法直接得知的真相
2. **可发现线索**：玩家通过仔细观察、搜索或特定行动可以发现的信息

**边界**：引用块只放玩家无法直接感知的信息。玩家一进房间就能看见的场景内容（生物、物体、明显的物品）写进朗读文本，不放入引用块。

不写具体发现方式，留给 GM 判断。

**示例**：

> 墙壁材质并非本地石材，来源不明的金属被混入其中
> 推倒脆弱的墙面会发出巨大声响，引起相邻房间的注意
> 墙面上似乎刻有某种符文或图腾，仔细辨认可发现是警告符号

#### 3.3 机制说明

**格式**：
- 使用###标题（如###陷阱门、###谜题、###魔法蘑菇圈），不用列表
- 机制要点直接写在标题下方，每个要点单独一行
- 空房间不需要机制说明

**完整性要求**：
- 机制说明必须完整，包含触发条件、解决方法、后果
- 陷阱：明确触发方式、伤害效果、规避方法
- 谜题：明确谜题内容、解决方法、奖励/惩罚
- 障碍：明确障碍类型、通过方法、失败后果
- 三要素自检：每个机制编写完成后自查——触发条件（何时生效）是否写明？解决方法（如何规避/解除）是否写明？后果（成功/失败的结果）是否写明？缺一项即补全，再写下一个房间
- 交易/谈判类机制分两种模式，按交易对象选用：
  - 固定服务表：适用于具体商品或服务的NPC交易（商人、工匠、赏金委托），每项服务都必须在当前冒险中有实际用途和明确收益，禁止无意义、给GM添麻烦或涉及未生成区域的选项
  - 自由许愿：适用于神秘存在（仙灵、法师、幽灵、神祇）交易。玩家自由说出愿望，GM按换算表估价，不用预设固定服务表。估价时把愿望拆成效果、目标、持续时间、范围逐项叠加；神秘存在能力有限，只做得到其等级能做到的事（高阶法师级做不到复活死者、凭空造物造钱、改变心智与爱情、跨界传送），做不到的直接拒绝或报天价警告

**自由许愿换算表（默认工具，价格量级可按战役经济调整）**：

| 难度 | 效果范围 | 估价 |
| --- | --- | --- |
| 小愿 | 一次性小效果：点火、照明、传讯、告知一件秘密、止疼 | d6×10p |
| 中愿 | 持续或强力效果：治疗、睡眠、解除普通诅咒、短期强化 | d6×50p |
| 大愿 | 永久或重大效果：解除强力诅咒、永久祝福、召唤或束缚 | d6×100p以上 |
| 拒绝 | 复活死者、凭空造物造钱、改变心智与爱情、跨界传送 | 拒绝或报天价警告 |
- 使用属性豁免（如"DEX豁免"），不写DC数值

**特殊效果表（可选工具）**：当房间机制包含幻觉、梦境等精神效果时（如"仙灵微光致幻"），机制标题下须写明触发条件、豁免类型、失败后果、脱离方式，并用 d6 表给出具体幻觉内容。示例：

| d6 | 幻觉内容 |
| --- | --- |
| 1 | 你看见一只毛皮雪白的老鼠坐在对面，回头对你笑，露出满嘴金牙 |
| 2 | 你听见熟人在身后喊你的名字，声音又近又急 |
| 3 | 脚下的地面变成流动的皮普河，每一步都像踩在钱堆上 |
| 4 | 你发现爪子里凭空多出一枚亮闪闪的东西，谁都没看见它怎么来的 |
| 5 | 周围的老鼠全都停下动作，齐刷刷转过来盯着你，眼神发亮 |
| 6 | 裂隙里伸出一只细长的手，掌心托着一枚皮普，像在等你接过 |

幻觉内容需贴合战役主题与核心秘密，禁写脱离主题的通用幻觉。

**唯一宝藏格式**：
- 房间的###宝藏章节下，每件唯一宝藏用 `####` 子标题分隔
- 名称自定，不与随机宝藏表关联
- 外观、用途、来源直接写在 `####` 子标题下的正文，不用 `>` 引用块二次声明

**### 宝藏章节出现条件**：
- 只有房间内放置了唯一宝藏时，才写 `### 宝藏` 章节
- 没有唯一宝藏的房间（包括只有 d6 表 roll 出宝藏的房间）不写该章节
- d6 随机表里的宝藏条目不进 `### 宝藏`，由 GM 在房间里掷骰决定

**宝藏 roll 标注**：
- 房间判定为"有"宝藏（见第2步宝藏判定表）时，在房间开头（朗读文本之前）用引用块标注可roll的宝藏表：
  - 最深处/核心秘密旁房间，或房间内放置主要级固定物品（如魔法剑、高价值宝物）：`> 主要宝藏`，GM可roll主要宝藏d6表
  - 其余有宝藏房间：`> 零散战利品`，GM可roll零散战利品d6表
  - 核心房间同时散落小物件：`> 主要宝藏/零散战利品`，两表皆可roll
- 无宝藏的房间不标注
- 标注行与`### 宝藏`唯一宝藏章节可同时存在，互不冲突

**派系归属标注**（可选）：
- 房间被某派系长期占据作为据点（巢穴/领地/祭祀所）时，可在宝藏标记下方另起一行 `> [派系名称][空间性质]`，如 `> 仙灵巢穴` `> 蜘蛛巢穴` `> 强盗营地`
- 该行标注派系身份，让 GM 在房间开头即可识别房间归属，与宝藏标记并存
- 派系归属信息已在第2步"生物判定"中确认，则必写；若派系仅在 GM 须知中描述，则选写
- 不替代任何机制说明，仅为视觉索引

#### 3.4 连接关系

有出口的房间使用"### 前进"作为标题，统一房间推进章节格式；没有出口的终点房间不写此章节。

**格式（D-09）**：每条连接固定占两行。第一行只写方向和目标，方向直接写"左/右/上/下/前"等，不加"向"，目标房间统一写作"房间N"；连接到冒险地点外部时，目标写作"外部出口"。第二行用引用块写路径场景，方向行不放引用块。路径场景只需选择一个最有辨识度的具体细节：实体、材质、动作或一种感官现象，写成15-28字的一句自然描述；不得重复第一行的目标，不强求堆叠多种感官。不能只写"通往某房间"、"来时通道"、势力归属、检定要求或其他路径简述。外部出口要写出口处的可见环境或可感知变化。禁止把冒号、房间名称或动作说明混入目标行。

### 前进

左 房间3
> 石门的铜钉泛着绿锈，门缝里透出一线冷风。

右 房间4
> 干草碎屑贴在石壁上，尽头有烛火晃动。

**多层结构软规则**：
- 若房间之间存在垂直连接（上下层、夹层、天花板破洞通向下方等），路径特征必须说明垂直距离和攀爬/跳跃难度
- 同一条物理路径被多个房间共享时（如同一竖井贯通三个房间），所有相关房间的 `### 前进` 必须使用一致的描述
- 回程方向同样按此格式，如"后 房间2"；路径场景仍须写具体的材质、痕迹、声音或动作，不得只写"来时通道"
